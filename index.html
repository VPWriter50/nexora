RESEARCH STANDARD

Methodology

The rules that keep project intelligence transparent, reproducible and useful.

Source hierarchy

Tier 1 · Primary sources

Official websites and documentation, project blogs, announcements, GitHub repositories, governance forums, ecosystem grant announcements, token contracts and blockchain explorers.

Tier 2 · Structured data providers

RootData for project/funding discovery; DefiLlama for relevant protocol metrics; GitHub API for repository activity. Check current terms, limits and attribution requirements before integration.

Tier 3 · Specialist sources

Launchpad calendars, testnet programmes, airdrop announcements, token unlock data, governance databases, security disclosures and licensed social data.

Claim verification

Every claim has its own evidence record

Store claim text, structured value, verification status, confidence, source URLs, excerpts, retrieval time and reviewer notes. Preserve previous claims when corrected.

Missing data is a valid result

Never fill absent team, funding, tokenomics or technical information with model assumptions. Mark unknown, undisclosed or not independently verified.

Lifecycle discipline

A token contract or announced date alone does not prove that a token launch occurred. Each milestone needs its own dated evidence.
